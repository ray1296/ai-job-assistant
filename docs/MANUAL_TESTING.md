# 手动测试流程与素材

## 目标

用合成数据把网站所有功能走一遍，先创建、再使用、最后统一删除，避免测试中途删除影响后续步骤。

## 准备

- 启动服务：app 目录下 node server/index.mjs（或 npm start）。
- 使用 Chromium/Chrome；测试前清一次 localStorage 或使用无痕窗口。
- 创建专用测试账号：qa-manual@example.invalid，密码只用测试密码。
- 管理员账号用 private/admin-initial.txt 中的凭据，不要用普通测试账号。
- 素材在 app/tests/fixtures/：
  - qa-jobs.csv
  - qa-housing.csv
  - qa-questions.txt
  - qa-knowledge.md
  - qa-resume.docx / qa-resume.pdf / qa-resume.png
- qa-data.xlsx（Excel 聊天附件测试）
- 测试前备份 app/private/career.sqlite（或整个 app/private），测试后删除测试账号。

## 建议顺序（关键）

先建、再用、最后删：

1. 账号
2. 个人信息 / 简历
3. 数据空间（岗位/租房上传）
4. 岗位 / 投递方案
5. 大屏 / 地图 / 企业 / 租房
6. 学习：建科目 → 建版本 → 上传/导入 → 刷题/收藏/错题 → AI 工具
7. 模拟面试
8. AI 协作空间 / RAG
9. 心愿池 / 管理中心
10. 个性化设置
11. 最后统一删除：数据集 → 学习版本 → 学习科目 → 测试账号

不要在“学习版本”还没测完时删除科目；不要在测试账号删除前删掉管理员会话；不要让真实账号参与上传。

## 删除顺序

1. 数据空间：删除 qa-jobs / qa-housing 数据集。
2. 学习：删除 QA 版本（先），再删除 QA 科目（后）。
3. 心愿池：删除测试心愿。
4. 简历：删除测试版本（保留测试账号到这一步）。
5. 管理中心：删除测试账号，级联清理资料/简历/面试/学习收藏。
6. 检查真实账号仍存在、数据完整。

## 失败时

- 先截图/记录页面错误和 Network 状态，不要连续点击。
- 上传类先看是否“服务器正在保留资源余量”（系统负载保护）或“当前有简历正在识别”；等 1–2 分钟再试。
- 需要回滚：停止服务，恢复测试前备份的 app/private/career.sqlite，再启动。
- 不要把真实 API Key、数据库、管理员密码粘贴到测试记录。
