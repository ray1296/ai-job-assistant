# 逐光预览环境资源预算与准入纪律

## 目标

用户要求“尽力做好而不拉满，为后续新增服务留余量”，不是寻找当前机器崩溃边界。效率、并发、稳定/可用/可靠、数据安全落实为预算、限额、可取消、可回退，不宣称理论QPS或生产HA。

## 当前观察（2026-10-20批次记录，瞬时值）

- 2逻辑核，MemTotal3718MiB；MemAvailable约2139–2251MiB；约20GiB磁盘余量。Swap已历史使用约1GiB，不代表可忽略内存压力。
- DSH、8090、MySQL及系统服务共机。本轮不修改其配置、不重启、不做全主机饱和压测。
- 单个合成PNG识别探针：墙钟0.77秒，最大子进程RSS97432KiB（约95MiB）；中文图实际浏览器含轮询约1.5秒。不同页面可能显著更慢，不能外推峰值QPS。

## 本批落实的保守限额

| 资源 | 限额/行为 |
|---|---|
| 大任务 | 全站同时1个识别，繁忙429，不设置无限队列 |
| 资源余量 | MemAvailable<1GiB、1分钟load>1.8或临时存储磁盘余量<1GiB，新的识别503；不主动停其他服务 |
| 文件 | ≤5MiB；PDF≤4页；PNG/JPEG≤1200万像素且长边≤6000；只接PDF/DOCX/PNG/JPEG |
| 时间 | 上传15秒；Python任务总预算68秒；外层75秒进程组硬终止；不无限重试 |
| 计算 | nice10；OMP_THREAD_LIMIT/OMP_NUM_THREADS/OpenBLAS=1 |
| 进程限额 | 512MiB地址空间/每进程；CPU65秒/每进程；单输出文件32MiB；nofile64 |
| 非聚合承诺 | 上述不是cgroup聚合内存硬限，也没有限制未来LLM的容量，不可当容器资源上限 |
| 临时结果 | 每账号4、全站24；15分钟有效，扫描清理最迟约16分钟；重启不恢复 |
| 数据 | 原件0700目录/0600文件，成功/失败/取消清理；非公开路由；不传第三方 |

编辑在前端进行，不逐键上传；服务端资料/版本写入原子revision比较冲突；Word依赖懒加载。识别进程异步运行，不在主事件循环解析文档，繁忙不影响普通资料读写。HTTP/全局IP速率限制是基础防滥用，不等于成熟网关；未来代理须设计可信来源IP，不能直接信X-Forwarded-For。

## 解析隔离与边界

解析器通过prlimit→nice→bwrap执行。独立网络/PID namespace，只读挂载/usr、lib、worker脚本、OCR工具目录；仅当前上传目录可写，应用目录、SQLite、凭据不挂载。缺少bwrap或权限不可用应失败，不自动回退无隔离执行。进程组取消与bwrap父进程死亡约束减少孤儿任务。仍需正式安全审计、依赖更新与恶意文件专项，不承诺绝对隔离。

## 可用性和扩容策略（仍待实施部分）

当前仍为单机单应用进程+SQLite，不是高可用架构。此次只提供任务限额/失败保留草稿/原子写入/清理，未做自动故障切换、灾备演练或SLA保证。上线前需HTTPS、备份恢复验证、进程守护、故障告警、权限终验与渐进负载测试。若低并发也频繁触发准入或响应变慢，应先降低页数/像素/队列并发，或把OCR迁到隔离worker；不得用关闭保护挤容量。主机新增服务后重新观察资源预算；不得把本次瞬时余量当长期承诺。

最终跨账号用户验收仍延期：全功能完成后覆盖资料、上传结果/附件、版本、导出、AI工具/RAG/图谱与管理员，不能用开发自测替代。
